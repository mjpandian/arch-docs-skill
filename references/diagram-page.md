# Interactive Diagram Page Specification

The interactive diagram page generated from `assets/diagrams.html` produces a self-contained, offline HTML/SVG architecture visualizer.

## Core Rules

- **Strict Offline Operation**: The page must function completely disconnected from the network. Never include external scripts, fonts, stylesheets, CDN links, or telemetry.
- **Evidence Backing**: Replace all sample entries in `DIAGRAMS` with project findings. Every node and edge must cite a valid `docs/ledger.json` ID (`F-####`).
- **No Invented Facts**: Do not carry forward illustrative sample nodes (e.g. hypothetical XML export, sample EHR).

## Node and Edge Data Contract

### Node Schema
```javascript
{
  id: "order_svc",                     // Unique identifier (used in edge from/to)
  label: "Order Processor",             // Primary title displayed on node
  tech: "Go / gRPC",                   // Technology/runtime (e.g. "FastAPI", "PostgreSQL 16")
  x: 300, y: 120, w: 190, h: 54,       // Canvas coordinates and dimensions
  src: "src/services/order.go:45",     // Source file:line or "external"
  repo: "order-service",               // Repository name (for filtering and cross-repo view)
  ledger: "F-0903",                    // Ledger entry ID in docs/ledger.json
  confidence: "verified",              // verified | inferred | doc-only | conflict | static-only | dead-candidate
  commit: "a1b2c3d",                   // Git commit SHA when verified
  sensitive: false,                    // true if handling PHI, PII, or credentials
  summary: "Coordinates order logic.", // Plain-English 1-2 sentence description
  detail: "Validates order items...",  // Technical notes displayed in side-panel
  model: []                            // Optional TLA+ model checking results
}
```

### Edge Schema
```javascript
{
  from: "user",                        // Source node id
  to: "gateway",                       // Target node id
  label: "1. Submit checkout",         // Edge label (protocol, step, or data type)
  ledger: "F-0911",                    // Ledger entry ID in docs/ledger.json
  confidence: "verified",              // Confidence level
  commit: "a1b2c3d",                   // Optional commit SHA
  model: []                            // Optional TLA+ model checking results
}
```

### Zone Schema
```javascript
{
  id: "client-zone",                   // Unique zone identifier
  label: "Client boundary",            // Zone heading
  x: 20, y: 50, w: 230, h: 380         // Bounding rectangle
}
```
*Note: In the cross-repo view, zone `id` matches the repository name.*

## 8 Required Views

1. **`app-flow`**: Request lifecycle from entry point to response, middleware ordering, and background worker queues.
2. **`data-flow`**: Input ingestion, validation, persistence, cache-aside read paths, change-data capture, and reporting.
3. **`integration-flow`**: Internal services and external third-party integrations with protocols and authentication tokens.
4. **`security-boundaries`**: Network/trust zones, edge TLS termination, authorization checkpoints, and sensitive data stores.
5. **`layering`**: Permitted architectural layer dependency directions (clients → controllers → services → repositories).
6. **`deployment`**: Runtime infrastructure topology, public vs private subnets, container replicas, and managed databases.
7. **`cross-repo`**: High-level repository grouping where edges represent verified interface contracts.
8. **`use-cases`**: Primary functional use case journeys with numbered sequential steps matching the animation player.

## Interactive Features

- **Animated Flow Stepper**: Step through use-case and application flows step by step (`Step 1 of N: A → B`).
- **Speed & Motion Controls**: Supports slow, normal, and fast speeds; automatically respects `prefers-reduced-motion`.
- **Repo Filter**: Dropdown to isolate and highlight components belonging to a chosen repository.
- **Verified Only Toggle**: Hides inferred, unverified, or dead-candidate nodes for clean stakeholder presentations.
- **Search Filter**: Real-time component matching across names, summaries, tech stacks, and ledger IDs.
- **Hotspot Heat Overlay**: Toggles color strips and `HOT`/`watch` rankings generated by `scripts/hotspots.py`.
- **Model Check Badges**: Displays `✖` for current behavior violations and `✓` for bounded invariants.
- **Integrity Status Footer**: Real-time validation of missing ledger IDs, unverified components, and dangling edge endpoints.
